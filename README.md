  # ZON

[Zig Object Notaion](https://cookbook.ziglang.cc/10-02-zon/) `ZON` is a textual file format used by the Zig programming language. Outside of `nan` and `inf` literals, ZON's grammar is a subset of Zig's. 

`zon` the library is a Go implementation of a ZON parser and serializer inspired by encoding/json. This library is generated by Claude Code, and operates on a refinement model. Bugs in parsing, serializing, or while using the command line app should be reported as issues according to [CONTRIBUTING.md](CONTRIBUTING.md).

The express goal of this library is to provide a simple, easy-to-use interface for parsing and serializing ZON data in Go with high performance and spec compliance. Failing to marshal spec-compliant data is a bug, and should be reported as such.

# Installation

```bash
go get github.com/tristanisham/zon
```

## Installing the CLI
```bash
go install github.com/tristanisham/zon/cmd/zon@latest
```

The `zon` CLI is a jq-like tool for working with ZON data. It allows you to query, filter, and transform ZON data from the command line.

## Usage

```
zon [flags] FILTER [files...]
```

`FILTER` is a jq filter expression. The CLI uses the [gojq](https://github.com/itchyny/gojq) engine, so standard jq syntax works. If omitted, `FILTER` defaults to `.` (identity).

The listed files are read in order. If no files are given, input is read from stdin.

### Flags

| Flag | Description |
| --- | --- |
| `--in auto\|zon\|json` | Input format. Default `auto` (auto-detects: input starting with `.` is treated as ZON, `{`/`[` as JSON; bare scalars try ZON then JSON). |
| `--to zon\|json\|yaml\|toml` | Output format. Default `zon`. |
| `-c`, `--compact` | Compact (single-line) output instead of pretty-printed. |
| `-r`, `--raw-output` | For string results, print the raw string without quotes; non-string results fall back to the chosen format. |
| `-n`, `--null-input` | Don't read input; run the filter once with `null` as input. |
| `-S`, `--sort-keys` | Sort object keys in the output. |
| `--version` | Print version. |
| `-h`, `--help` | Print help. |

### Examples

These examples assume a `build.zig.zon` shaped like:

```zon
.{
    .name = .my_project,
    .version = "0.1.0",
    .dependencies = .{
        .mecha = .{
            .url = "https://example.com/mecha.tar.gz",
            .hash = "1220abcd...",
        },
    },
    .paths = .{
        "build.zig",
        "src",
    },
}
```

Pretty-print / reformat a ZON file (output is ZON by default):

```bash
zon . build.zig.zon
```

Extract a field (output is ZON):

```bash
zon '.name' build.zig.zon
```

Convert ZON to JSON:

```bash
zon --to json . build.zig.zon
```

```json
{
  "name": "my_project",
  "version": "0.1.0",
  "dependencies": {
    "mecha": {
      "url": "https://example.com/mecha.tar.gz",
      "hash": "1220abcd..."
    }
  },
  "paths": [
    "build.zig",
    "src"
  ]
}
```

Convert JSON to ZON from stdin:

```bash
cat data.json | zon --in json --to zon .
```

Get a raw string value (no surrounding quotes):

```bash
zon -r '.version' build.zig.zon
```

```
0.1.0
```

List dependency names:

```bash
zon '.dependencies | keys' build.zig.zon
```

Compact JSON output:

```bash
zon -c --to json . build.zig.zon
```

```json
{"name":"my_project","version":"0.1.0","dependencies":{"mecha":{"url":"https://example.com/mecha.tar.gz","hash":"1220abcd..."}},"paths":["build.zig","src"]}
```

### Notes and limitations (v1)

- **Enum literals decode to strings.** A value like `.debug` becomes `"debug"`, so a ZON→ZON round trip through a filter loses the enum-ness (it comes back as a quoted string rather than an enum literal).
- **TOML output requires a top-level table.** The result must be an object (table); emitting a bare scalar or array as TOML is an error.
